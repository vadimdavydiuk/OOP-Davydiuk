# Звіт: самостійна робота №8

## Реалізація та результати

Cache<TKey, TValue> поєднує Dictionary для доступу за ключем і Queue для порядку вставлення. Конструктор відхиляє нульову та від'ємну ємність. Додавання нового ключа в повний кеш спочатку видаляє ключ із початку черги та словника. Повторне додавання наявного ключа оновлює значення без зміни порядку: це FIFO, а не LRU.

Get використовує TryGetValue та самостійно викидає KeyNotFoundException. ContainsKey перевіряє наявність, Count відображає кількість пар. Читання елемента не робить його новішим. Колекція призначена для послідовного використання; синхронізація між потоками не є частиною завдання.

Окремий проєкт IndependentWork7.Tests посилається на основний. Пройшли всі 10 тестів: порожній кеш, додавання/отримання, ContainsKey, відсутній ключ, витіснення після читання, оновлення ключа без зміни FIFO, багато витіснень, ємність 1 і два невалідних значення ємності. Результат: 10 пройдено, 0 помилок.

## Контрольні запитання

1. Generics дозволяють використовувати один алгоритм для різних типів без небезпечних приведень та з перевіркою типів компілятором. Обмеження TKey : notnull відповідає вимогам Dictionary.
2. Dictionary забезпечує середній доступ за ключем O(1), а Queue — додавання в кінець і видалення найстарішого за O(1). Окремо словник не визначає політику витіснення.
3. Get викидає виняток, коли його контракт вимагає наявності ключа. Якщо відсутність очікувана, зручніше TryGetValue або перевірка ContainsKey.
4. Потрібні перевірки повної ємності, повторного ключа, порядку після Get, багаторазового витіснення та незмінності Count при переповненні.

## Висновок

FIFO-кеш обмежує використання пам'яті кількістю елементів, зберігаючи простий алгоритм витіснення. Оновлення та читання не змінюють порядок вставлення; саме це відрізняє реалізацію від LRU. Тести перевіряють поведінку на межі ємності та після кількох послідовних змін.
