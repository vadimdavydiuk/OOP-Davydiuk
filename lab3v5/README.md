## Мета
Навчитися працювати з некерованими ресурсами, реалізувати інтерфейс `IDisposable` та патерн `Dispose`.

## Короткий висновок
1. **`using`** — автоматично викликає `Dispose()` після завершення блоку. Найбезпечніший спосіб.
2. **Явний `Dispose()`** — викликається вручну для негайного звільнення ресурсів.
3. **Деструктор (`GC.Collect()`)** — спрацьовує як аварійна страховка, якщо розробник забув викликати `Dispose()`.

## Відповіді на контрольні запитання
1. **Життєвий цикл в .NET:** Створення об'єкта в купі $\rightarrow$ Використання $\rightarrow$ Збирання сміття (GC) $\rightarrow$ Фіналізація.
2. **Керовані vs некеровані ресурси:** Керовані (пам'ять .NET) очищає GC. Некеровані (файли, контексти, БД) вимагають ручного звільнення.
3. **IDisposable:** Інтерфейс для явного звільнення некерованих ресурсів через метод `Dispose()`.
4. **Оператор using:** Автоматично гарантує виклик `Dispose()`, навіть при виникненні помилок (`try-finally`).
5. **GC.SuppressFinalize(this):** Відключає викликання деструктора для об'єкта, оскільки ресурси вже звільнені вручну.
6. **Dispose(true) vs Dispose(false):** `Dispose(true)` звільняє керовані й некеровані ресурси (викликається вручну/`using`). `Dispose(false)` викликається деструктором і очищає лише некеровані ресурси.
